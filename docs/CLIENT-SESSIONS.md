# 本地 Client 会话与薄记忆

Relay 使用用户本地安装的 Harness。本地会话中心的同步对象是本地 Client 的原生会话，包含用户在 CLI、桌面 Client 等入口发起的对话。首版接入 Codex；Claude Code、OpenCode 的解析器后续按同一服务边界扩展。

## 用户流程

左侧 **本地会话** 查看归档，可按项目过滤，搜索标题、工作目录或原生会话 ID。项目标题旁的本地会话入口直接查看该项目的会话。

项目归属先用原生会话的工作目录匹配 Relay 配置的项目工作目录，只有唯一匹配时自动归属。多个项目使用同一目录时保持未归属。用户可手动指定项目或设为未归属，该选择在同步和重启后保留。

选择会话后查看用户与助手的可见文字。为控制界面开销，列表显示最多 200 个匹配会话，详情显示最近 80 条消息；长消息显示 12,000 字预览，可复制全文。归档保存完整可见文字，搜索覆盖全部会话目录。

会话 UI 不提供手动保存项目记忆的操作，记忆由项目主 Agent 维护，写入接口仍待接入。原生会话内容、标题和归档不会自动加入 Jev 请求或 ACP 上下文；已有项目记忆继续参与后续上下文交付。记忆仍沿用每条 4,000 字、每项目 32 条及项目上下文总额限制，已有原生 Client、会话 ID 和记录字节位置来源保持可读。

## 快照与增量

启动时同步一次，每次同步结束后等待 **30 分钟**，也可点击立即同步。该间隔只控制本地会话归档；项目资料与记忆仍随下一条 ACP 消息交付。

Codex 来源为 `$CODEX_HOME/sessions` 和 `$CODEX_HOME/archived_sessions`，未设置时使用 `~/.codex`。读取 JSONL 的 `session_meta` 与 `response_item` 中的可见用户/助手文字，忽略开发者指令、推理、工具输出、重复事件和已知环境注入项。不连接或接管用户已经运行的对话。

每个会话保存自己的归档、最后完整记录的字节位置及已提交前缀的 SHA-256。文件长度、修改时间和文件身份均未变化时跳过；变化时校验已提交前缀，追加只解析新增完整行，截短或改写则重新建立当前快照。校验变更文件的旧前缀仍需读取旧字节，不重复解析、生成摘要或调用模型。未写完的尾行不推进游标。

原生会话 ID 用于去重，移动到 archived_sessions 后保留项目归属。原始文件只读。损坏的完整记录不推进快照；读取失败时保留已有归档。源文件消失后保留已导入的记录并显示来源不可用。未知版本或损坏的 Relay 归档、目录不会被覆盖。

单条 JSONL 记录读取上限为 64 MB，超出时保留已有快照并提示同步失败；压缩上下文等非对话记录不会写入归档。Relay 归档被删除而来源仍在时，下次同步可重新建立快照。

## 存储与边界

```text
Relay/
  client-sessions/index.json       # 会话目录、归属、来源文件状态、同步时间
  client-sessions/archives/<hash>.json  # 完整可见文字及同步游标
  projects.json                   # 项目事实与决策
```

归档与目录采用 0600 文件权限及原子替换。目录只保存元数据；打开会话时在后台加载文字。导入与项目归属不执行模型请求，不修改原生记录，不把大量会话转成事实。

保存本地会话来源的记忆时，项目目录升级到 v3；普通项目和已有 v1/v2 目录继续可读。旧应用拒绝 v3，避免丢弃原生来源。

现阶段是只读导入。原生会话续聊需要对应 Harness 的恢复协议及运行状态支持，尚未提供；任务线程执行与主 Agent 委派仍是独立后续工作。
