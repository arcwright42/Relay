# 本地 Client 会话与原生记忆

Relay 使用用户本地安装的 Harness。本地会话中心的同步对象是本地 Client 的原生会话，包含用户在 CLI、桌面 Client 等入口发起的对话。首版接入 Codex；Claude Code、OpenCode 的解析器后续按同一服务边界扩展。

## 用户流程

左侧 **本地会话** 查看归档，可按任务过滤，搜索标题、工作目录或原生会话 ID。任务标题旁的本地会话入口直接查看该任务的会话。

任务归属先用原生会话的工作目录匹配 Relay 配置的任务工作目录，只有唯一匹配时自动归属。多个任务使用同一目录时保持未归属。用户可手动指定任务或设为未归属，该选择在同步和重启后保留。

选择会话后查看用户与助手的可见文字。为控制界面开销，列表显示最多 200 个匹配会话，详情显示最近 80 条消息；长消息显示 12,000 字预览，可复制全文。归档保存完整可见文字，搜索覆盖全部会话目录。

归档完成后由原生记忆 worker 增量读取：按消息分组和大小拆分为来源片段、建立全文索引，再通过独立 observer 提炼候选与主题。用户可以在主对话中查找跨 session 线索和来源，不必先分配给某个任务。归档 ID 与任务 ID 保持独立；同一个 session 可以属于多个主题。详见 [原生记忆](NATIVE-MEMORY.md)。

## 快照与增量

启动时同步一次，每次同步结束后等待 **30 分钟**，也可点击立即同步。该间隔只控制本地会话归档；任务资料与记忆仍随下一条 ACP 消息交付。

Codex 来源为 `$CODEX_HOME/sessions` 和 `$CODEX_HOME/archived_sessions`，未设置时使用 `~/.codex`。读取 JSONL 的 `session_meta` 与 `response_item` 中的可见用户/助手文字，忽略开发者指令、推理、工具输出、重复事件和已知环境注入项。不连接或接管用户已经运行的对话。

每个会话保存自己的归档、最后完整记录的字节位置及已提交前缀的 SHA-256。文件长度、修改时间和文件身份均未变化时跳过；变化时校验已提交前缀，追加只解析新增完整行，截短或改写则重新建立当前快照。校验变更文件的旧前缀仍需读取旧字节，不重复解析、生成摘要或调用模型。未写完的尾行不推进游标。

原生会话 ID 用于去重，移动到 archived_sessions 后保留任务归属。原始文件只读。损坏的完整记录不推进快照；读取失败时保留已有归档。源文件消失后保留已导入的记录并显示来源不可用。未知版本或损坏的 Relay 归档、目录不会被覆盖。

单条 JSONL 记录读取上限为 64 MB，超出时保留已有快照并提示同步失败；压缩上下文等非对话记录不会写入归档。Relay 归档被删除而来源仍在时，下次同步可重新建立快照。

## 存储与边界

```text
Relay/
  client-sessions/index.json       # 会话目录、归属、来源文件状态、同步时间
  client-sessions/archives/<hash>.json  # 完整可见文字及同步游标
  relay.sqlite3                   # 来源版本、提炼队列、记忆、主题和任务
```

归档与目录采用 0600 文件权限及原子替换。目录只保存元数据；打开会话时在后台加载文字。导入与手动关联本身不执行模型请求、不修改原生记录；后台记忆提炼单独遵循开关和每小时预算。完成提炼前也可使用原文索引。

外部 session 仍是只读导入，尚不支持接管原生运行中会话或原生续聊。Relay 内部独立任务已经实现，使用新的 ACP session；内部 session 和 observer 输出不重复当作外部记忆来源。
