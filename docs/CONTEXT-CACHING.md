# 项目上下文与前缀缓存落地方案

本次范围：真实项目、文字资料、版本化上下文、ACP 会话增量同步、延迟与用量观测。UI 与实现继续使用 Rust；不新增 crate 或第三方依赖。主 Agent 委派、全文检索、文件/网页/图片导入为后续工作。

## 职责与数据

| 层 | 本次职责 |
| --- | --- |
| relay-core | Project / ContextItem、ProjectService、对话诊断类型；保持零依赖 |
| relay-runtime::projects | 项目目录、指令、文字资料、乐观版本检查、原子保存；不绑定 Agent |
| relay-runtime::context | 确定性快照、按资料 ID 排序的增量、会话同步检查点 |
| relay-runtime | 将上下文变化追加到 ACP prompt；原生恢复、失败处理、耗时记录 |
| relay-acp | 将 ACP 响应、结束原因与可选用量转换为领域事件 |
| relay-ui | 创建/编辑项目、文字资料管理、双语对话诊断；不访问文件或 ACP SDK |

项目定义独立保存在 projects.json；既有 projects/<id>/conversation.json 保留原位置并升级格式。首次升级只迁移有已存对话的旧项目 1–3，保留 ID 和历史，不导入示例资料。新安装创建一个可编辑的真实空项目。项目及资料 ID 单调分配，不复用现有目录。损坏、未来版本及无效数据保留原样并阻止覆盖。

项目修改携带预期版本，过时编辑被拒绝。保存完成后才发布新快照，磁盘失败不把未保存内容当作已生效上下文。磁盘操作在后台执行，内存快照可供 UI 快速读取。

## 上下文协议

1. 每个项目保存名称、说明、项目指令和文字资料。资料可选择是否提供给 Agent。资料数量、单项长度和已选内容总量有明确上限；超限拒绝保存，不静默截断。
2. 首次发送：按资料 ID 排序，生成固定格式的项目快照，不加入时间、随机数、界面语言或运行状态。
3. 后续发送：比较当前项目与该原生会话上次确认的快照。无变化不附加上下文；有变化只追加修改的指令/资料及移除 ID。编辑未选资料不重复注入已选内容。
4. 增量含项目、基线版本、目标版本及稳定内容摘要。明确新值替代旧值；移除资料意味着后续不再作为有效项目材料，并不承诺从 Agent 已有历史中删除。
5. 发送期间的项目更新留到下一轮；确认的是该轮发送时的快照，不提前推进到最新项目版本。
6. 发送前持久化未确认状态，保存失败不发送请求。正常结束后推进会话检查点；仅修改未选资料时不推进 Agent 已知版本。拒绝、请求失败、取消及连接中断保留原检查点并标记不确定，下一次用户主动发送时追加当前完整快照。这样即使用户撤销了未确认修改，也不会将旧状态误判为已同步。不自动重发用户任务；ACP 不提供上下文事务回执，异常边界允许重复追加，不能承诺 exactly-once。
7. 原生 session/load 成功：保留同步检查点，不重发已确认上下文。新会话或恢复失败：重置检查点，发送当前快照，再附加有界近期历史。优先级说明确保当前项目资料覆盖恢复历史中的过时项目资料。
8. 模型/推理选项切换不篡改历史或重复创建会话。Harness 负责模型缓存、工具定义和原生压缩；Relay 不直接写 provider cache_control，也不为维持 TTL 自动发送收费请求。

本次未接入独立的压缩通知或手动压缩入口；Harness 自动压缩时由其保留会话语义。未来接入压缩生命周期后，在明确边界刷新项目快照，不能根据 token 数下降擅自判断已发生压缩。

项目数据库属于长期知识层；会话检查点只描述已经交付的版本，不代表服务端缓存仍然存在。更换模型、前缀变化、TTL 到期均可能使缓存失效。

## 观测口径

- 首字延迟：Relay 接受发送到首个非空 assistant 文本块，不将工具事件或思考状态当作首字。
- 总耗时：发送到 ACP 终态，包含工具执行、审批等待和网络时间，不能等同模型计算时间。
- 持久化当前模型、上下文交付方式/版本/字节数、是否补入历史、可选 token 用量。
- 固定的 codex-acp 1.12.0 的 prompt usage 来自 lastTokenUsage；inputTokens 排除了 cachedInputTokens。展示为“最近一次模型请求”，不是整轮或整个会话总量。
- 对这个已验证适配器，缓存读取占比 = cachedRead / (input + cachedRead + cachedWrite)。缺失可选缓存读取字段时显示未提供；零读取与未提供严格区分，不从本地快照推算命中率。未提供写入计数的 Codex 按 0 写入计入该适配器口径。
- Rust SDK 仅开启固定版本的 unstable_end_turn_token_usage feature，隔离在 relay-acp；响应缺失/损坏的 usage 不影响对话。其他 Harness 接入前须单独核对计数语义。

## 验收

- 项目创建/编辑、资料选择/修改/移除、重启保存和旧项目迁移。
- 相同状态生成逐字相同 payload；无变化不重发；单项更新不携带未变资料；移除产生明确的撤回记录。
- 项目隔离、过时编辑、输入大小上限、损坏文件保护、保存失败回滚。
- 原生恢复不重复注入；恢复失败重新建快照；失败/拒绝/取消不提前确认；发送中更新下一轮生效；旧连接事件不能更新新检查点。
- ACP 测试子进程验证文本顺序、结束原因、可选用量，使用离线测试不产生模型费用。
- GPUI 验证动态项目、资料入口、语言切换和诊断；cargo xtask verify 检查包治理、格式、Clippy 和全工作区测试。
