# Relay 产品规格

需求更新：2026-10-05。此版采用持续主对话、按需委派任务和 Claude-Mem 记忆 Provider，取代以 Project 为必经容器以及 Jev prompt 归属判断。首个可用 Harness 为本地 Codex。

## 产品定位

Relay 是面向个人用户的原生桌面 Agent 入口。用户一直与 Relay 沟通，Relay 通过记忆 Provider 保留可检索的偏好、决定与工作线索，并按需要启动和跟进独立任务。UI 和核心使用 Rust，采用 GPUI + GPUI Kit，macOS 优先。

“本地”指应用、数据及 Harness 运行位置；模型推理与 ASR/TTS 是否联网取决于所选服务。Relay 连接本地已有安装，不管理 Harness 本体的安装升级。

## 主对话、任务与记忆

| 概念 | 用户行为与实现 |
| --- | --- |
| 主对话 | 首页、全局快捷入口、语音默认进入同一个 Relay thread；改变话题不会创建新会话 |
| 任务 thread | 主 Agent 为独立执行工作创建，侧栏与活动页可打开查看、追问和处理授权 |
| ACP session | thread 下可恢复或替换的执行上下文，不能作为长期身份 |
| 记忆 | Claude-Mem 生成的观察、会话总结与工作线索；记录不代表用户已确认 |
| 个人文件 | 所有任务共享的成果与文件目录，不按 thread 划分 |

用户从任务详情或显式任务选择进入时，输入属于该任务。其他输入进入主对话。Agent 可以基于上下文调用 `continue_task`，也可以创建独立任务；不确定“继续哪个”时澄清，不能仅凭主题接近自动改投。一个主对话轮次可以协调多个任务。

主 Agent 通过 Relay MCP 读取任务、委派工作、记录交接及检索记忆。记忆提炼由独立 Claude-Mem Worker 完成，Relay 保留 Provider 抽象、事件投递和作用域校验。记忆页面可搜索、查看观察、重试明确失败的投递和删除单条观察。原 Native 引擎及其确认、版本修订、来源遗忘、主题页和预算操作已移除。

## 用户入口

- 主窗口以 Relay 对话为首页；侧栏展示任务与历史 thread，活动页展示实际任务状态。
- `⌃⌥Space` 取得当前选区与可用 URL，默认交给 Relay；可明确选择任务。抓取未完成不阻塞发送，迟到网页正文不改写已发送内容。
- 小窗与工作台共享目标 thread 的消息和连接，各窗口保留自己的未发送草稿。展开保持目标；不会因快捷面板另建项目。
- 语音唤醒默认关闭。开启后说“嘿 relay / Hey Relay”，或在设置中开始语音会话。处理和播放阶段暂停收音，结束后继续听；Esc 或结束按钮回到等待唤醒，关闭开关或退出应用释放麦克风。

无法取得选区时允许直接输入；不使用旧内容填补缺失。系统权限、认证和工具授权均展示实际状态。授权在目标任务或主对话处理，Worker 的模型配置和授权独立于 Relay。

## 资料、产物与上下文

thread 保留目标、指令和选用文字资料。资料单条上限 12,000 字符，最多 64 条，选用资料和指令合计最多 32,000 字符；修改在下一条消息生效，不改变在途轮次。资料编辑不是记忆确认操作。

任务成果保存到统一个人文件空间，文件 Tab 自动发现。文本编辑有外部修改检测，冲突时保留草稿、支持另存副本。对话的本地文件链接可以跳到文件预览。具体设计见 [个人文件工作区](PERSONAL-FILES.md)。

每轮追加必要的角色、有限任务状态；记忆上下文按 disabled/session/turn 配置注入。完整历史、详细记忆和来源按需检索，主 Agent 对证据进行取舍，不把全部历史一次送给模型。持久记忆独立于 Harness，上下文缓存由 Harness/模型控制，不承诺跨模型共享缓存。

## 一致性与用户控制

任务创建先返回持久 ID，排队不表示执行完成。正在执行的任务需要权限时标记等待；执行结束先进入待检查，由主 Agent 审阅后才标记完成。进程退出时未知投递标记中断，重启后不自动重做可能有副作用的操作。

Claude-Mem 自己管理提炼模型、Chroma 与运行额度，不依赖 Relay 主对话先连接。Worker 离线时事件留在 Relay 队列，Agent 的本轮任务仍可继续，读取失败明确显示。投递结果不确定时先检查 Worker，再显式重试、确认接收或放弃，避免盲目重复调用。

删除观察仅删除这条记录，原始 prompt、工具事件、总结和 Relay 聊天档案保留。历史归档不接管外部 Client 会话。旧记忆数据不自动迁移，也不自动转交旧 Embedding Key。

## 迁移、验收与后续

旧 Project 变为历史 thread，原始目录和会话文件保留。新的主对话固定独立身份；旧薄记忆保留原文件，不自动提炼。旧 Jev 配置不再使用，无需新的路由服务或密钥。

验收包括跨话题保持主对话、显式任务继续、异步结果回收、授权和取消的轮次关联、重启不重复执行、Worker 离线与不确定投递、旧数据兼容、作用域隔离以及 MCP 在 ACP 新建/恢复时可用。详细技术边界与测试见 [Memory Provider](MEMORY-PROVIDERS.md)。

后续工作包括更多 Harness、外部原生 session 续聊、向量检索与聚类质量评测、向量聚类图、跨设备备份、截图及持续视觉。当前不以这些能力作为已实现功能对外呈现。
